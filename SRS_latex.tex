\section{Introduction}

This Software Requirements Specification (SRS) document specifies the software requirements for the role-based internal platform for the Santa Barbara Public Defender's Office. The platform is built with SharePoint Framework (SPFx) and is designed to display content targeted to the user's Active Directory role. This document has been updated to reflect the final delivered system as of May 2026.

This SRS document covers the final delivered version of the system and reflects all features implemented across the Fall 2025 and Spring 2026 semesters. \subsection{Product Scope}

The product is a web-based intranet platform designed for internal use by the Santa Barbara County Public Defender's Office. The platform allows authenticated users to view role-appropriate resources and documents, access necessary forms, search for staff and expert witnesses, manage office desk reservations, track case assignments, complete training and compliance assignments, and receive role-filtered announcements and events. The platform is implemented using SharePoint Framework (SPFx) with React and TypeScript, deployed to SharePoint Online under the county's Microsoft 365 tenant. Role-based access is managed automatically through Azure Active Directory (Entra ID) security group membership. No manual SharePoint permission administration is required when staff join, change roles, or leave the organization. The platform delivers nine distinct user experiences from a single SharePoint site and codebase, organized around the following role hierarchy from highest to lowest privilege: IT, Compliance

Officer, HR, Trial Supervisor, Attorney, CDD (Capital Defense Division), LOP (Legal Office Professionals), PD-Intranet (general authenticated staff), and Everyone (Guest/unauthenticated).

\section{Overall Description}

\subsection{System Analysis}

Prior to this project the Santa Barbara County Public Defender's Office relied on a legacy SharePoint site (PD Internal) that provided a flat, role-unaware experience. All staff saw identical content regardless of their role or department. Resources were scattered across email, shared drives, physical binders, and outdated intranet pages. IT staff managed SharePoint permissions manually, creating delays when employees changed roles or left the organization. The PD-Intranet platform replaces this system with a unified hub that delivers personalized, role-filtered content automatically through Azure Active Directory synchronization. The system eliminates manual permission management entirely and provides each of nine distinct staff roles with a tailored intranet experience from a single SharePoint site.

\subsection{Product Perspective}

The PD-Intranet is a new system that replaces the existing legacy SharePoint intranet. It operates entirely within the county's Microsoft 365 ecosystem, leveraging SharePoint Online as the hosting platform, Azure Active Directory (Entra ID) for identity and access management, Microsoft Graph API for calendar and organizational data, PowerBI for embedded analytics, and Azure Functions for backend processing operations. The system is not a standalone application. It is a collection of SPFx web parts deployed to a SharePoint Communication Site. All data is stored in SharePoint lists. All authentication is handled by Microsoft 365 and Entra ID. No external hosting infrastructure is required.

\subsection{Product Functions}

The platform delivers the following primary functions:

\begin{itemize}[leftmargin=*]
\item  Role-based navigation: the site header dynamically renders navigation tabs based on the user's Active Directory group membership. IT administrators see all tabs; Guest users see one.
\item  Personalized content delivery: web parts render role-appropriate content. Unauthorized web parts hide entirely or display a restricted access message.
\item  Announcements: role-filtered news and updates tagged by department. IT users see all announcements; other roles see only their department's content.
\item  Upcoming Events and Calendar: displays events from multiple SharePoint sites and the user's Outlook calendar with role-filtered results.
\item  Staff Directory: searchable employee contact database accessible to all authenticated users.
\item  Expert Witness Directory: searchable database of expert witnesses with availability status and specialty filtering.
\item  Office Hoteling: real-time desk reservation system with weekly availability calendar, email confirmation, and conflict detection. Visible to IT, PD-Intranet, Attorney, CDD, and LOP roles.
\end{itemize}

\begin{itemize}[leftmargin=*]
\item  Attorney Workload Tracker: hierarchical case distribution visibility (Location $\rightarrow$ Case Type $\rightarrow$ Attorney) for Trial Supervisor, HR, and IT roles.
\item  LOP Procedure Checklist: searchable procedure library for Legal Office Professionals with step-by-step workflows, PDF attachments, YouTube video embeds, and IT-managed PDF import.
\item  CDD Resource Guides: hierarchical document library for Capital Defense Division staff with search, multi-select, and email sharing.
\item  Urgency Portal (PowerBI): embedded analytics dashboard restricted to IT and Trial Supervisor roles.
\item  Assignments: training, acknowledgement, and task management system with step-by-step completion tracking, video embeds, quiz gates, and Azure Function-backed verification.
\item  Content Management System (CMS): IT-only interface for managing announcements, events, forms, assignments, and site banners.
\item  Zero manual permission management: all access control is driven by Active Directory group membership with automatic synchronization to SharePoint.
\end{itemize}

\section{External Interface Requirements}

\subsection{User Interfaces}

The primary user interface is a SharePoint modern communication site rendered in the user's web browser. The site uses a consistent layout across all role views with a header navigation bar, a main content area containing SPFx web parts, and a right sidebar for quick-access panels (Office Information, Staff Directory, Assignments, Expert Witness Directory). Web parts use consistent card and collapsible panel design patterns built with React and Tailwind CSS utility classes via the Fluent UI design system. The interface is responsive and adapts to tablet and mobile viewport sizes. The CMS provides an administrative interface for IT administrators accessible from the same SharePoint page via role-gated navigation links.

\subsection{Hardware Interfaces}

The platform has no direct hardware interface requirements. It operates through standard web browser environments on county-issued devices. The platform accesses the device's network interface through the browser for all SharePoint and Microsoft Graph API communications.

\subsection{Software Interfaces}

\subsubsection{SharePoint Online}

The platform is hosted on SharePoint Online as a Communication Site. SPFx web parts are deployed via the SharePoint App Catalog. SharePoint lists serve as the primary data store. The PnP.js library provides the primary interface for SharePoint REST API operations.

\subsubsection{Azure Active Directory / Entra ID}

All authentication and authorization is handled through Azure Entra ID. The PDRoleBasedSelect component reads the user's group membership from Entra ID at runtime to determine which role view to render. Security group membership in Entra ID drives all permission decisions.

\subsubsection{Microsoft Graph API}

The Microsoft Graph API is used for Outlook calendar integration (Upcoming Events web part), organizational data access, and Azure Function authentication via EasyAuth. The MSGraphClientFactory SPFx service provides authenticated Graph API access within web parts.

\subsubsection{Azure Functions}

Azure Functions provide the backend compute layer for two features: PortalAssignmentsMutate (quiz submission verification, assignment progress updates, and calendar event creation) and LopProcedureChecklistImport (PDF-to-procedure-steps conversion pipeline). Functions are authenticated via Azure AD EasyAuth.

\subsubsection{PowerBI}

The Urgency Portal web part embeds PowerBI reports and visuals via configurable iframe URLs. PowerBI licensing in the county's Microsoft 365 tenant is required for dashboard access.

\subsection{Communications Interfaces}

All client-server communication uses HTTPS. SharePoint REST API calls use OAuth tokens issued by Entra ID. Microsoft Graph API calls use delegated permissions with MFA-verified user tokens. Azure Function calls use AadHttpClient with EasyAuth token validation. No custom communication protocols are used.

\section{Requirements Specification}

\subsection{Functional Requirements}

\subsection*{FR-RB: Role-Based Access Control}

FR-RB1: The system shall support nine user roles defined by Azure Active Directory security group membership: IT, Compliance Officer, HR, Trial Supervisor, Attorney, CDD, LOP, PD-Intranet, and Everyone (Guest). FR-RB2: The system shall apply role priority in the following order when a user belongs to multiple groups (highest to lowest): IT, Compliance Officer, HR, Trial Supervisor, Attorney, CDD, LOP, PD-Intranet, Everyone. FR-RB3: The site navigation header shall display only the tabs appropriate to the user's role. IT administrators shall see all tabs. Guest users shall see only the Everyone tab. FR-RB4: Permission changes shall take effect automatically when a user's Active Directory group membership changes. No manual SharePoint administrator action shall be required. FR-RB5: Web parts shall check the user's role at runtime via PDRoleBasedSelect and render only authorized content. Unauthorized web parts shall render empty or display a restricted access message.

\subsection*{FR-AN: Announcements}

FR-AN1: The Announcements web part shall display role-filtered announcements from a SharePoint list. Each announcement shall be tagged with a PDDepartment field matched against the user's role. FR-AN2: IT administrators shall see all announcements regardless of department tag. FR-AN3: The web part shall display up to 12 recent announcements per load including title, summary, author, publish date, and expiry date.

\subsection*{FR-EV: Events and Calendar}

FR-EV1: The Upcoming Events web part shall display events from multiple SharePoint calendar sources and the user's Outlook calendar. FR-EV2: Events shall be displayed in a collapsible table with date, time, title, location, and a details link. FR-EV3: The web part shall use caching to display previously loaded events immediately while fetching updated data in the background.

\subsection*{FR-SD: Staff Directory}

FR-SD1: The Staff Directory web part shall display employee contact records including name, title, phone, extension, and cell number. FR-SD2: The web part shall support client-side search filtering across all visible fields. FR-SD3: The Staff Directory shall be visible to all authenticated user roles.

\subsection*{FR-EW: Expert Witness Directory}

FR-EW1: The Expert Witness Directory web part shall display a searchable database of expert witnesses. FR-EW2: Each record shall display name, specialty, availability status, contact information, and field of expertise. FR-EW3: The directory shall be visible to all authenticated user roles.

\subsection*{FR-OH: Office Hoteling}

FR-OH1: The Office Hoteling web part shall allow authorized users to reserve office desks for Morning (8am-12pm) or Afternoon (12pm-5pm) time slots. FR-OH2: Users shall be able to select a location (North County, South County, Juvenile, Lompoc) and a station before viewing availability. FR-OH3: The weekly availability calendar shall display Available, Booked, and Past states with color coding. FR-OH4: Reservations shall be stored in the HotelingReservations SharePoint list. FR-OH5: Email confirmation shall be sent upon successful booking. FR-OH6: Delete shall be disabled within 24 hours of the reservation time. FR-OH7: The web part shall be visible only to IT, PD-Intranet, Attorney, CDD, and LOP roles.

\subsection*{FR-AW: Attorney Workload Tracker}

FR-AW1: The Attorney Workload Tracker shall display hierarchical case distribution data organized by Location, Case Type, and Attorney. FR-AW2: The full workload view shall be restricted to Trial Supervisor, HR, and IT roles. FR-AW3: All other roles shall see a restricted access message. FR-AW4: The interface shall support search and filter functionality across the case hierarchy.

\subsection*{FR-LP: LOP Procedure Checklist}

FR-LP1: The LOP Procedure Checklist shall provide a searchable library of office procedures organized by category. FR-LP2: Each procedure shall contain ordered steps with support for rich text content, PDF attachments, and YouTube video embeds. FR-LP3: IT administrators shall have edit access. All authenticated users shall be able to view procedures. FR-LP4: IT administrators shall be able to import PDFs as structured procedure steps via the LopProcedureChecklistImport Azure Function. FR-LP5: Procedures shall be stored in the LOPProcedureChecklist and ProcedureSteps SharePoint lists.

\subsection*{FR-CD: CDD Resource Guides}

FR-CD1: The CDD Resource Guides web part shall display a hierarchical document library organized by category and subcategory.

FR-CD2: The web part shall support multi-word search across document names, metadata tags, and folder names. FR-CD3: Users shall be able to select multiple documents and share them via a generated mailto link. FR-CD4: The web part shall support both SharePoint files and external links stored as .url files. FR-CD5: The web part shall be visible to CDD and IT roles.

\subsection*{FR-UP: Urgency Portal}

FR-UP1: The Urgency Portal web part shall embed a configurable PowerBI dashboard within the SharePoint page. FR-UP2: The web part shall support configurable report URL, visual URL, carousel mode, and visible count properties. FR-UP3: Access shall be restricted to IT and Trial Supervisor roles only.

\subsection*{FR-AS: Assignments}

FR-AS1: The Assignments web part shall support three assignment types: Training, Acknowledgement, and Task. FR-AS2: Training assignments shall support sequential steps with rich text content, video embed completion tracking, and quiz gates. FR-AS3: Quiz answers shall be submitted to the PortalAssignmentsMutate Azure Function for server-side verification. FR-AS4: Assignment progress including current step, percent complete, and completion status shall be stored in the Assignments SharePoint list. FR-AS5: Administrators shall manage the assignment catalog and individual user assignments through the CMS web part. FR-AS6: The Assignments web part shall display a My Assignments view and an Open Assignments Page link for all authenticated users.

\subsection*{FR-CM: Content Management System}

FR-CM1: The CMS web part shall provide IT administrators with a centralized management interface for announcements, events, forms, assignments, assignment catalog, banners, and submissions. FR-CM2: The CMS shall support an Audience Picker for targeting content to specific roles. FR-CM3: CMS access shall be restricted to IT administrators and authorized content owners.

\section{Legal and Ethical Considerations}

The platform operates within the Santa Barbara Public Defender's Office's Microsoft 365 SharePoint environment, ensuring that all information is stored securely and remains confidential. User access is managed through Microsoft Entra ID (Azure Active Directory), which verifies each user's identity, assigns the correct permissions, and enforces Multi-Factor Authentication for added security. No personal or sensitive data is shared outside of the county's Microsoft 365 environment. All access is strictly role-based to protect privacy and maintain confidentiality. The system does not collect or store any data outside of SharePoint Online and Azure services provided by Microsoft under the county's enterprise agreement. The platform handles attorney-client privileged information by design --- role-based access controls ensure that only authorized personnel can access case-related tools and documents. The system is designed to uphold strong legal and ethical standards by safeguarding user information, ensuring data integrity, and providing fair and secure access for all authorized staff.

\section{Appendix A: Glossary}

Azure Functions: Microsoft's serverless compute platform used for backend operations including quiz submission verification (PortalAssignmentsMutate) and LOP PDF import processing (LopProcedureChecklistImport). CDD (Capital Defense Division): A specialized unit within the Public Defender's Office handling capital cases. CMS (Content Management System): The set of SharePoint lists, pages, and SPFx components used by IT administrators to manage announcements, forms, events, assignments, and site banners. Entra ID (Azure Active Directory): Microsoft's cloud identity and access management service used for authentication and role group assignments. LOP (Legal Office Professionals): Staff responsible for office procedures, case opening workflows, and administrative legal tasks. PDRoleBasedSelect: Custom SPFx React component that reads the user's Azure Entra ID group membership at runtime and renders the appropriate role-based view. PnP.js (Patterns and Practices): Open-source JavaScript library providing a fluent API for SharePoint REST operations. Role-Based Content: Content that is shown or hidden depending on the user's Active Directory security group membership. SPFx (SharePoint Framework): A client-side development model for building custom web parts and extensions in SharePoint Online using React and TypeScript. Web Part: A reusable SPFx UI component placed on SharePoint pages to display data or provide functionality. .sppkg: The compiled SharePoint package file uploaded to the App Catalog for deployment.
